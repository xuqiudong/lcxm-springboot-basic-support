# 平行越权基础组件
> 平行越权本质应该是做好数据权限的管理，这个部分由项目自身解决。
> 当前组件期望: 通过隐藏真实ID，降低平行越权暴露面

## 设计思路
### 提供id加解密方案。
   - 提供默认的SALT, 具体项目应该提供运行时SALT， 如sessionId(可变)/username(不变)
   - 对加密id结果进行wrap, 方便识别方便加密
   - 支持文本中的加密id的解密，比如多id逗号分隔，比如长文本中包含的id
### 提供解密Filter
> 要不要使用：OncePerRequestFilter  内部额转发的时候要不要
  - 需支持: Form表单, json，文件上传中的id解密
  - 注意支持请求体重读 

### 提供抽象切面加密(具体项目继承重写): 在controller中return切面中进行加密处理
> 考虑需要自定义切点(兼容现有代码) + 注解切点，  可以使用 MethodInterceptor +  AbstractPointcutAdvisor 的方式
  - 仅支持返回BaseResponse (具体项目中可重写覆盖？)
  - 方法上如果包含 SkipIdEncrypt 注解，则不进行加密  (到底是包含某注解就加密, 还是包含此注解)
  - 单对象需要实现 IdEncryptable (get/set Id)
  - 对某些特定对象特地处理, 如List, Map,PageInfo等
  - 设置某些加密的字段名 （一般是外键，比如xxxId） 是要加注解呢 还是这里也可以统一指定一些常见的外键名
  - 遍历对象的时候 深度限制, 比如 递归深度为4 (子类也可以配置)
  - 也可以设置某些url默认跳过加密

### 基础 抽象配置， 由项目自行定义扩展部分
 - id加密的盐值提供：运行时SALT 最好可变
 - 自定义切点提供 （ + 默认提供注解的切点）
 - 加密处理逻辑中 一些模板功能实现
