# 第三方入站接口文档

## 调用流程

```text
1. 第三方按固定规则生成 sign。
2. 第三方调用获取 token 接口。
3. 核心系统校验 appId、timestamp、username、sign。
4. 校验成功返回 token。
5. 第三方携带 token 请求业务接口。
6. 核心系统通过拦截器校验 token。
7. token 有效则进入业务接口。
8. token 不再使用时，可调用注销 token 接口。
```

## 获取 Token

```text
POST /inbound/api/obtain-token
Content-Type: application/json
```

请求参数：

```json
{
  "sign": "xxxxx",
  "appId": "demo",
  "timestamp": 1778568450708,
  "username": "kingdee",
  "nonce": "123-abc"
}
```

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| sign | String | 是 | 请求签名 |
| appId | String | 是 | 第三方应用标识 |
| timestamp | Long | 是 | 毫秒时间戳，默认允许与服务端相差 5 分钟 |
| username | String | 是 | 分配给第三方的用户名 |
| nonce | String | 否 | 随机字符串；核心系统启用 nonce 防重时必填 |

响应示例：

```json
{
  "code": 0,
  "msg": "",
  "data": "12344555"
}
```

`data` 为 token 字符串。

token 默认有效期 60 分钟。核心系统可按 `appId` 单独调整有效期，第三方应在本地按有效期缓存并在过期前重新获取。

## 携带 Token 访问业务接口

具体业务接口由双方另行约定。

统一规则：

- 业务 URL 建议统一放在 `/inbound/api/` 前缀下。
- 请求业务接口时必须携带 token。
- header 默认使用 `X-Third-Token`，避免与业务 header、网关鉴权 header 或其他 token header 冲突。

推荐传递方式：

```text
X-Third-Token: xxxxxx
```

兼容传递方式：

```text
Query/Form: token=xxxxxx
```

Header 优先级高于参数。具体项目如需兼容旧协议，可通过配置基类自定义 header 名称为 `token`。

## 注销 Token

```text
POST /inbound/api/revoke-token
Content-Type: application/x-www-form-urlencoded
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| token | String | 是 | 需要注销的 token |

请求示例：

```text
/inbound/api/revoke-token?token=12344555
```

响应示例：

```json
{
  "code": 0,
  "msg": "",
  "data": {
    "appId": "demo",
    "thirdCode": "kingdee",
    "username": "kingdee",
    "expireAt": "2026-07-29 12:00:00"
  }
}
```

注销成功后，该 token 不能继续访问业务接口。

## Sign 签名规则

签名算法：

```text
SHA256withRSA
```

密钥规则：

- 第三方系统持有 RSA 私钥。
- 第三方系统使用私钥对签名原文签名。
- 核心系统使用对应公钥验签。
- sign 结果使用 Base64 字符串传输。

签名原文按以下固定顺序拼接：

```text
appId={appId}&timestamp={timestamp}&nonce={nonce}&username={username}
```

示例：

```text
appId=demo&timestamp=1778568450708&nonce=123-abc&username=kingdee
```

注意：

- `appId`、`nonce`、`username` 按 UTF-8 query 参数规则编码后参与签名。
- `timestamp` 使用毫秒时间戳。
- 未启用 nonce 防重时，`nonce` 可以为空；启用后不能为空且同一时间窗内不能重复。

## Hutool RSA 示例

以下示例只说明签名和验签规则。第三方只需要私钥签名；核心系统使用公钥验签。

```java
import java.nio.charset.StandardCharsets;

import cn.hutool.core.codec.Base64;
import cn.hutool.core.date.DateUtil;
import cn.hutool.core.util.URLUtil;
import cn.hutool.crypto.SignUtil;
import cn.hutool.crypto.asymmetric.RSA;
import cn.hutool.crypto.asymmetric.Sign;
import cn.hutool.crypto.asymmetric.SignAlgorithm;

public class ThirdSignDemo {

    public static void main(String[] args) {
        RSA rsa = new RSA();
        String publicKey = rsa.getPublicKeyBase64();
        String privateKey = rsa.getPrivateKeyBase64();

        long timestamp = DateUtil.current();
        String payload = buildTokenPayload("demo", "123-abc", timestamp, "kingdee");

        String sign = privateSign(payload, privateKey);
        boolean verified = publicVerify(sign, payload, publicKey);

        System.out.println("payload = " + payload);
        System.out.println("sign = " + sign);
        System.out.println("verified = " + verified);
    }

    private static String buildTokenPayload(String appId, String nonce, long timestamp, String username) {
        return "appId=" + encode(appId)
                + "&timestamp=" + timestamp
                + "&nonce=" + encode(nonce)
                + "&username=" + encode(username);
    }

    private static String privateSign(String data, String privateKey) {
        Sign sign = SignUtil.sign(SignAlgorithm.SHA256withRSA, privateKey, null);
        return Base64.encode(sign.sign(data.getBytes(StandardCharsets.UTF_8)));
    }

    private static boolean publicVerify(String signContent, String content, String publicKey) {
        Sign sign = SignUtil.sign(SignAlgorithm.SHA256withRSA, null, publicKey);
        return sign.verify(content.getBytes(StandardCharsets.UTF_8), Base64.decode(signContent));
    }

    private static String encode(String value) {
        return URLUtil.encodeQuery(value == null ? "" : value);
    }
}
```
