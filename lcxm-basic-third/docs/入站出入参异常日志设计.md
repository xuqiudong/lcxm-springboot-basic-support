# 入站出入参异常日志设计

## 目标

第三方请求我方业务接口时，记录业务方法级别的调用日志。

核心配置只有一个：`InboundInvokeLogAspect`。

- `@InboundLog` / `@InboundLogIgnore`：告诉切面记录什么、忽略什么。
- `InboundInvokeLog`：切面最终组装出的日志模型。
- `InboundInvokeContextHolder`：业务代码补充第三方标识、业务类型、外部单号等上下文。
- `InboundInvokeLogUtils`：参数过滤、JSON 序列化、异常堆栈转换。
- `Slf4jInboundInvokeLogger`：默认打印日志。
- `InboundInvokeLogger`：项目自定义入库、MQ、审计扩展。

## 边界

AOP 只记录进入业务方法后的调用情况：

- 正常进入方法：记录入参、出参、耗时。
- 方法抛异常：记录入参、异常、耗时，并继续抛出原异常。
- `void` 返回值：出参记录为 `[void]`。

不记录：

- token 拦截器直接拒绝、未进入业务方法的请求。
- 原始 request body / response body。
- header 审计。

```text

|   `-- Slf4jInboundInvokeLogger      # 默认 slf4j 打印实现

```

## 注解

固定第三方接口：

```java
@InboundLog(thirdCode = "kingdee", operation = "订单推送")
@PostMapping("/kingdee/order")
public BaseResponse<?> order(@RequestBody KingdeeOrderRequest request) {
    ...
}
```

通用入口：

```java
@InboundLog(operation = "通用消息接收")
@PostMapping("/message")
public BaseResponse<?> receive(@RequestBody CommonThirdMessage message) {
    InboundInvokeContextHolder.put("thirdCode", message.getThirdCode());
    InboundInvokeContextHolder.put("bizType", message.getBizType());
    InboundInvokeContextHolder.put("outRequestNo", message.getRequestNo());
    ...
}
```

参数级忽略：

```java
@InboundLog(operation = "订单推送")
@PostMapping("/order")
public BaseResponse<?> order(@RequestBody OrderRequest request,
                             @InboundLogIgnore UploadContext uploadContext) {
    ...
}
```

说明：

- `@InboundLogIgnore` 只影响日志切面，不组合 Jackson 注解。
- DTO 字段忽略继续使用业务已有的 Jackson 注解，例如 `@JsonIgnore`，保持日志序列化和业务序列化一致。

## 上下文

上下文使用一个对象统一持有 `Map<String, Object>`。

```java
InboundInvokeContextHolder.put("thirdCode", "kingdee");
InboundInvokeContextHolder.put("bizType", "order");
InboundInvokeContextHolder.put("orderNo", "O-001");
```

规则：

- `@InboundLog.thirdCode` 是固定接口默认值。
- `context.thirdCode` 存在时覆盖注解值。
- AOP 在 `finally` 中读取 context 后执行 `clear()`，避免线程复用污染。

## 参数过滤

默认忽略以下类型：

```text
ServletRequest
ServletResponse
HttpSession
MultipartFile
File
InputStream
OutputStream
byte[]
InputStreamSource
BindingResult
Model
ModelMap
```

处理策略：

- 普通 DTO：转 JSON。
- `MultipartFile`：只记录文件摘要，不记录内容。
- 文件、流、字节数组：记录占位符，不记录内容。
- `void` 返回值：记录 `[void]`。
- 序列化失败：记录 `[serialize failed: 异常信息]`。

项目可在配置类中额外补充忽略类型：

```java
@Override
protected Class<?>[] inboundInvokeExtraIgnoreTypes() {
    return new Class<?>[] {ThirdUploadContext.class, LargePayload.class};
}
```

## 异常记录

异常信息是核心能力，内置记录：

```text
exceptionClass
exceptionMessage
exceptionStack
```

规则：

- 捕获 `Throwable`。
- 记录异常后继续抛出原异常。
- 不改变业务异常处理流程。
- `exceptionStack` 由 `@InboundLog.exceptionStack()` 控制。

## 日志落点

入站日志只有两个动作：

- 默认 slf4j 打印：由 `printInboundInvokeLog()` 控制，只用于排查。
- 项目自定义处理：由 `customInboundInvokeLogger()` 返回值决定，通常用于入库、MQ 或审计。

自定义处理接口：

```java
public interface InboundInvokeLogger {

    void log(InboundInvokeLog log);
}
```

`Slf4jInboundInvokeLogger` 只裁剪打印内容，不修改 `InboundInvokeLog` 模型本身。入库是否裁剪由项目实现决定。

## 配置

`AbstractThirdInboundConfiguration` 已提供入站日志切面：

```java
@Override
protected boolean printInboundInvokeLog() {
    return true;
}

@Override
protected int inboundInvokeSlf4jTextMaxLength() {
    return 4000;
}

@Override
protected InboundInvokeLogger customInboundInvokeLogger() {
    return new DbInboundInvokeLogger();
}

@Override
protected Class<?>[] inboundInvokeExtraIgnoreTypes() {
    return new Class<?>[] {ThirdUploadContext.class, LargePayload.class};
}
```

含义：

- `printInboundInvokeLog()` 控制是否打印默认 slf4j 日志。
- `inboundInvokeSlf4jTextMaxLength()` 只裁剪 slf4j 打印文本，不修改日志模型。
- `customInboundInvokeLogger()` 控制是否额外入库、MQ 或审计。
- `inboundInvokeExtraIgnoreTypes()` 补充当前项目不适合记录的参数类型。
- slf4j 和自定义处理互不替代，可以同时生效。
