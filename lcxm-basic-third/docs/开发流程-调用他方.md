# 开发流程：我方调用第三方

## 目标

每个第三方一个业务 Client，公共模块处理 HTTP 执行、响应解析和日志扩展点。

```text
业务服务
  -> 某第三方 Client
  -> OutboundRequestInfo
  -> HttpOutboundExecutor
  -> 第三方接口
```

公共模块负责：

- HTTP 执行、query/form/body 处理、header 合并。
- JSON 响应解析、特殊响应解析扩展。
- 常见包装泛型响应的 JavaType 构建。
- 出站异常包装、耗时统计、交换日志模型。

具体 Client 负责：

- 厂商 URL、header、签名、token、密钥、业务参数。
- 具体业务方法和厂商业务错误码处理。

## 开发步骤

1. 写项目配置类。

继承 `AbstractThirdOutboundConfiguration`，并在项目配置类上添加 `@Configuration`。

```java
@Configuration
public class ThirdOutboundConfiguration extends AbstractThirdOutboundConfiguration {

    @Override
    protected ThirdExchangeLogger customThirdExchangeLogger() {
        return new DbThirdExchangeLogger();
    }
}
```

`DbThirdExchangeLogger` 是项目侧实现，用于落库、MQ 或审计。

基类默认提供：

- `ThirdExchangeLogger`

2. 定义第三方标识和配置来源。

业务项目维护 `thirdCode`、baseUrl、超时、默认 header、密钥、厂商参数等。

公共模块只提供：

- `ThirdIdentity`
- `ThirdClientOptions`

项目侧自行从配置文件、数据库或缓存读取参数，并组装为 `ThirdClientOptions`。

3. 编写第三方 Client。

继承 `AbstractOutboundClient`：

```java
public class KingdeeOutboundClient extends AbstractOutboundClient {

    public KingdeeOutboundClient(ThirdClientOptions options, OutboundExecutor outboundExecutor) {
        super(options, outboundExecutor);
    }

    @Override
    protected ThirdIdentity thirdIdentity() {
        return new ThirdIdentity("kingdee", "金蝶");
    }

    @Override
    protected String buildUrl(String path) {
        return "https://example.com" + path;
    }

    @Override
    protected Map<String, String> buildHeaders() {
        Map<String, String> headers = new LinkedHashMap<>();
        headers.put("Content-Type", "application/json");
        return headers;
    }
}
```

4. 在配置类中声明第三方 Client。

```java
@Bean
public KingdeeOutboundClient kingdeeOutboundClient(ThirdExchangeLogger exchangeLogger) {
    ThirdClientOptions options = buildKingdeeOptions();
    OutboundExecutor executor = new HttpOutboundExecutor(options, null, exchangeLogger);
    return new KingdeeOutboundClient(options, executor);
}
```

`buildKingdeeOptions()` 是项目侧自定义方法，可以从配置文件、数据库或缓存读取参数。

5. 在业务方法中构建请求。

```java
OutboundRequestInfo<MyResponse> request = builder(MyResponse.class)
        .operation("submit-demo")
        .method(ThirdHttpMethod.POST)
        .url(buildUrl("/api/demo"))
        .body(body)
        .responseType(MyResponse.class)
        .build();

return execute(request);
```

6. 处理特殊响应。

标准 JSON 走默认解析。非标准 JSON、纯文本、文件地址等，用 `OutboundResponseParser`。
包装泛型响应可使用 `ResponseTypeUtils`，或直接调用 builder 的
`wrapperResponseType(...)`、`wrapperListResponseType(...)`。

7. 处理交换日志。

默认由 `CompositeThirdExchangeLogger` 组合 slf4j 日志。需要落库、MQ、审计时覆盖
`customThirdExchangeLogger()` 返回项目侧 logger。
自定义 logger 存在时仍会打印 slf4j；如需关闭打印，覆盖 `printThirdExchangeLog()` 返回 `false`。
不需要记录出站交换日志时，将对应 `ThirdClientOptions.exchangeLogEnabled` 设置为 `false`。
默认 slf4j 打印请求体、响应体、异常信息时会裁剪，覆盖 `thirdSlf4jExchangeLogTextMaxLength()` 可调整，
默认 4000 字符，设置为小于等于 0 表示不裁剪。`ThirdExchangeLog` 模型本身保留完整文本，
项目自定义 logger 入库时自行决定是否裁剪。

## 注意点

- 配置基类不加 `@Configuration`，项目继承类自己加。
- 不把具体厂商参数沉到公共模块。
- 不在公共模块维护第三方枚举。
- HTTP 状态码大于等于 400 时，默认执行器抛 `ThirdException`。
- token 缓存、密钥轮换、厂商业务错误码，由业务项目按厂商规则处理。
- HTTP 默认使用 Hutool；确实需要替换时实现 `OutboundExecutor`。
