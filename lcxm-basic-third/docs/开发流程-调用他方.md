# 开发流程：我方调用第三方

## 目标

每个第三方一个业务 Client，公共模块处理 HTTP 执行、响应解析和日志扩展点。

```text
业务服务
  -> 某第三方 Client
  -> ThirdApi
  -> OutboundRequestInfo
  -> HttpOutboundExecutor
  -> 第三方接口
```

公共模块负责：

- HTTP 执行、query/form/body 处理、header 合并。
- 厂商 API 枚举接口、host 拼接、厂商配置模型和短缓存。
- JSON/FORM/TEXT/BYTES 请求类型识别和 Content-Type/Accept 默认处理。
- JSON 响应解析、特殊响应解析扩展。
- 常见包装泛型响应的 JavaType 构建。
- 出站异常包装、耗时统计、交换日志模型。

具体 Client 负责：

- 厂商 URL 枚举、header、签名、token、密钥、业务参数。
- 具体业务方法和厂商业务错误码处理。

## 开发步骤

1. 写出站全局配置类。

继承 `AbstractThirdOutboundConfiguration`，并在项目配置类上添加 `@Configuration`。
全局配置只做公共 bean 装配：交换日志、厂商 client。

```java
@Configuration
public class ThirdOutboundConfiguration extends AbstractThirdOutboundConfiguration {

    @Bean
    public KingdeeOutboundClient kingdeeOutboundClient(KingdeeConfigService kingdeeConfigService,
            ThirdExchangeLogger exchangeLogger) {
        ThirdClientOptions options = new ThirdClientOptions();
        OutboundExecutor executor = new HttpOutboundExecutor(options, null, exchangeLogger);
        return new KingdeeOutboundClient(kingdeeConfigService, options, executor);
    }

    @Override
    protected ThirdExchangeLogger customThirdExchangeLogger() {
        return new DbThirdExchangeLogger();
    }
}
```

`DbThirdExchangeLogger` 是项目侧实现，用于落库、MQ 或审计。

基类默认提供：

- `ThirdExchangeLogger`

2. 按 partner 拆分厂商实现。

建议结构：

```text
third
|-- inbound
|   |-- config
|   |   `-- ThirdInboundConfiguration     # 入站方向全局配置
|   `-- partner
|       `-- kingdee
|           |-- config
|           |   `-- KingdeeInboundAppConfigRegistry
|           `-- controller
|               `-- KingdeeInboundController
`-- outbound
    |-- config
    |   `-- ThirdOutboundConfiguration    # 出站方向全局配置和 bean 装配
    `-- partner
        `-- kingdee
            |-- client
            |   `-- KingdeeOutboundClient # 厂商调用入口
            |-- config
            |   `-- KingdeeConfig         # 厂商配置模型
            |-- enums
            |   `-- KingdeeApi            # 厂商 API 枚举
            `-- model
                |-- request
                |-- response
                `-- KingdeeResponse       # 厂商响应包装
```

方向级 `config` 放公共装配；具体厂商的枚举、模型、Client 只放在自己的 `partner/xxx` 下。
如果多个厂商确实共享对象，再在对应方向下增加 `common`，不要提前建空包。

仓库 `src/test/java/cn/xuqiudong/basic/third/demo/outbound` 下有可编译 demo。
demo 不进入正式 jar，业务项目只通过 Maven 依赖时看不到，需要看仓库源码。

3. 定义第三方 API 枚举和配置模型。

业务项目维护 `thirdCode`、host、超时、默认 header、密钥、厂商参数等。

公共模块只提供：

- `ThirdIdentity`
- `ThirdClientOptions`
- `ThirdApi`
- `OutboundPartnerConfig`

项目侧自行从配置文件、数据库、Redis 或配置中心读取参数，并组装厂商配置模型。
配置模型是运行时数据，不建议直接声明为 Spring bean；配置取值逻辑由具体 Client 或项目配置服务自行管理。
`AbstractOutboundPartner` 默认会对 `loadConfig()` 的返回结果做 Caffeine 短缓存，默认 5 分钟。

```java
public enum KingdeeApi implements ThirdApi {
    GET_TOKEN("获取 Token", "/token", ThirdHttpMethod.POST, "0"),
    VOUCHER_SUBMIT("保存凭证", "/voucher/submit", ThirdHttpMethod.POST, "0000");

    private final String apiName;
    private final String path;
    private final ThirdHttpMethod method;
    private final String successCode;

    KingdeeApi(String apiName, String path, ThirdHttpMethod method, String successCode) {
        this.apiName = apiName;
        this.path = path;
        this.method = method;
        this.successCode = successCode;
    }

    public String getApiName() { return apiName; }
    public String getPath() { return path; }
    public ThirdHttpMethod getMethod() { return method; }
    public String getSuccessCode() { return successCode; }
}
```

4. 编写第三方 Client。

优先继承 `AbstractOutboundPartner<C>`：

```java
public class KingdeeOutboundClient extends AbstractOutboundPartner<KingdeeConfig> {

    private final KingdeeConfigService kingdeeConfigService;

    public KingdeeOutboundClient(KingdeeConfigService kingdeeConfigService,
            ThirdClientOptions options, OutboundExecutor outboundExecutor) {
        super(options, outboundExecutor);
        this.kingdeeConfigService = kingdeeConfigService;
    }

    @Override
    protected ThirdIdentity thirdIdentity() {
        return new ThirdIdentity("kingdee", "金蝶");
    }

    @Override
    protected KingdeeConfig loadConfig() {
        return kingdeeConfigService.loadConfig();
    }

    @Override
    protected Map<String, String> buildHeaders(ThirdApi api) {
        Map<String, String> headers = new LinkedHashMap<>();
        headers.put("accessToken", getToken());
        return headers;
    }
}
```

5. 在配置类中声明第三方 Client。

```java
@Bean
public KingdeeOutboundClient kingdeeOutboundClient(KingdeeConfigService kingdeeConfigService,
        ThirdExchangeLogger exchangeLogger) {
    ThirdClientOptions options = buildKingdeeOptions();
    OutboundExecutor executor = new HttpOutboundExecutor(options, null, exchangeLogger);
    return new KingdeeOutboundClient(kingdeeConfigService, options, executor);
}
```

`loadConfig()` 由具体 Client 实现，可以从配置文件、数据库、Redis 或配置中心读取配置。
基类默认缓存 5 分钟；如需调整时间，覆盖 `configCacheTtl()`；返回小于等于 0 的时间表示不缓存。

6. 在业务方法中构建请求。

```java
OutboundRequestInfo<MyResponse> request = builder(KingdeeApi.VOUCHER_SUBMIT, MyResponse.class)
        .operation("submit-demo")
        .jsonBody(body)
        .build();

return execute(KingdeeApi.VOUCHER_SUBMIT, request);
```

常见 JSON POST 可直接封装为厂商方法：

```java
public <T extends BaseKingdeeRequest, R extends BaseKingdeeResponse>
KingdeeResponse<R> request(KingdeeApi api, T body, Class<R> responseType) {
    JavaType type = ResponseTypeUtils.objectType(KingdeeResponse.class, responseType);
    return request(api, body, type);
}
```

7. 处理特殊响应。

标准 JSON 走默认解析。非标准 JSON、纯文本、文件地址等，用 `OutboundResponseParser`。
包装泛型响应可使用 `ResponseTypeUtils`，或直接调用 builder 的
`wrapperResponseType(...)`、`wrapperListResponseType(...)`。

8. 处理交换日志。

默认由 `CompositeThirdExchangeLogger` 组合 slf4j 日志。需要落库、MQ、审计时覆盖
`customThirdExchangeLogger()` 返回项目侧 logger。
自定义 logger 存在时仍会打印 slf4j；如需关闭打印，覆盖 `printThirdExchangeLog()` 返回 `false`。
不需要记录出站交换日志时，将对应 `ThirdClientOptions.exchangeLogEnabled` 设置为 `false`。
默认 slf4j 打印请求体、响应体、异常信息时会裁剪，覆盖 `thirdSlf4jExchangeLogTextMaxLength()` 可调整，
默认 4000 字符，设置为小于等于 0 表示不裁剪。`ThirdExchangeLog` 模型本身保留完整文本，
项目自定义 logger 入库时自行决定是否裁剪。

## 注意点

- 配置基类不加 `@Configuration`，项目继承类自己加。
- 不把具体厂商参数沉到公共模块。
- 公共模块只提供 `ThirdApi` 接口，不维护具体第三方枚举。
- 简单 HTTP 底座可直接继承 `AbstractOutboundClient`；常规厂商对接优先继承 `AbstractOutboundPartner`。
- HTTP 状态码大于等于 400 时，默认执行器抛 `ThirdException`。
- token 缓存、密钥轮换、厂商业务错误码，由业务项目按厂商规则处理。
- HTTP 默认使用 Hutool；确实需要替换时实现 `OutboundExecutor`。
