# 开发流程：第三方接入我方

## 目标

第三方通过 `obtain-token` 获取 token，然后携带 token 调用我方业务接口。

```text
第三方
  -> /inbound/api/obtain-token
  -> X-Third-Token
  -> 我方业务 Controller
```

建议结构：

```text
third
|-- inbound
|   |-- config
|   |   `-- ThirdInboundConfiguration     # 入站方向全局配置：store、token controller、interceptor
|   `-- partner
|       `-- kingdee
|           |-- config
|           |   `-- KingdeeInboundAppConfigRegistry # appId、公钥、用户、TTL、nonce 开关
|           `-- controller
|               `-- KingdeeInboundController        # 第三方请求我方的业务接口
`-- outbound
    |-- config
    |   `-- ThirdOutboundConfiguration    # 出站方向全局配置
    `-- partner
        `-- kingdee
            |-- client
            |-- config
            |-- enums
            `-- model
```

方向级 `config` 放公共装配；具体第三方的 app 配置、业务接口放在自己的 `partner/xxx` 下。
多个第三方确实共享对象时，再在方向下增加 `common`。

仓库 `src/test/java/cn/xuqiudong/basic/third/demo/inbound` 下有可编译 demo。
demo 不进入正式 jar，业务项目只通过 Maven 依赖时看不到，需要看仓库源码。

## 开发步骤

1. 写项目配置类。

继承 `AbstractThirdInboundConfiguration`，并在项目配置类上添加 `@Configuration`。

```java
@Configuration
public class ThirdInboundConfiguration extends AbstractThirdInboundConfiguration {

    private final RedisTemplate<String, Object> redisTemplate;

    public ThirdInboundConfiguration(RedisTemplate<String, Object> redisTemplate) {
        this.redisTemplate = redisTemplate;
    }

    @Override
    protected RedisTemplate<String, Object> inboundRedisTemplate() {
        return redisTemplate;
    }
}
```

基类默认提供：

- `InboundTokenService`
- `InboundTokenController`
- `InboundTokenInterceptor`
- `/inbound/api/**` 拦截路径
- `/inbound/api/obtain-token`、`/inbound/api/revoke-token` 排除路径
- header `X-Third-Token`、参数 `token`

2. 提供第三方配置注册点。

推荐一个第三方一个 `InboundAppConfigRegistry`：

```java
@Component
public class KingdeeInboundAppConfigRegistry implements InboundAppConfigRegistry {

    @Override
    public String thirdCode() {
        return "kingdee";
    }

    @Override
    public InboundAppConfig inboundConfig() {
        InboundAppConfig config = new InboundAppConfig();
        config.setAppId("kingdee-app");
        config.setPublicKey(publicKey);
        config.addUsername("kingdee");
        return config;
    }
}
```

3. 按需开启 nonce 防重。

是否校验 nonce 由每个 `InboundAppConfig.nonceRequired` 决定。配置基类默认已经使用同一个
`RedisTemplate` 创建 `RedisNonceStore`，项目侧不需要再单独配置 nonce 存储。

如需切换为 Caffeine 本地存储，覆盖 `useInboundRedisStore()` 返回 `false`。

4. 按需覆盖拦截规则。

```java
@Override
protected String[] inboundInterceptPathPatterns() {
    return new String[] {"/open-api/**"};
}
```

如需兼容旧 header：

```java
@Override
protected String inboundTokenHeaderName() {
    return "token";
}
```

如果 Spring MVC XML 中已经手动注册 `InboundTokenInterceptor`，关闭 Java Config 自动注册：

```java
@Override
protected boolean registerInboundTokenInterceptor() {
    return false;
}
```

XML 注册拦截器时，`tokenHeaderName` 和 `tokenParameterName` 可以不配置，默认分别为
`X-Third-Token` 和 `token`：

```xml
<bean id="inboundTokenInterceptor"
      class="cn.xuqiudong.basic.third.inbound.web.interceptor.InboundTokenInterceptor">
    <property name="tokenService" ref="inboundTokenService"/>
</bean>

<mvc:interceptors>
    <mvc:interceptor>
        <mvc:mapping path="/inbound/api/**"/>
        <mvc:exclude-mapping path="/inbound/api/obtain-token"/>
        <mvc:exclude-mapping path="/inbound/api/revoke-token"/>
        <ref bean="inboundTokenInterceptor"/>
    </mvc:interceptor>
</mvc:interceptors>
```

5. 编写业务 Controller。

业务 URL 建议继续放在 `/inbound/api/` 下，由项目自己定义响应模型和业务语义。

## 注意点

- 配置基类不加 `@Configuration`，项目继承类自己加。
- 默认 token 和 nonce 存储都使用 Redis，项目需要提供 `inboundRedisTemplate()`。
- 测试或单机场景如需 Caffeine，覆盖 `useInboundRedisStore()` 返回 `false`。
- `/inbound/api/obtain-token` 不能被 token 拦截。
- `/inbound/api/revoke-token` 默认不拦截，接口自身会校验 token 是否有效。
- 默认 token controller 已做异常兜底，对第三方返回 `BaseResponse.error`，避免 token 接口直接暴露 HTTP 500。
- 不要在 Java Config 和 XML 中重复注册同一个 `InboundTokenInterceptor`。
- 如果项目有全局登录认证，需要排除第三方入站 URL。
- 对外接口说明给第三方看：[第三方入站接口文档.md](第三方入站接口文档.md)。
